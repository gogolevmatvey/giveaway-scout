# Сервер статистики Giveaway Scout

Отдельный сервис на Rust: HTTP обрабатывают [Hyper](https://hyper.rs/guides/1/server/hello-world/) и Tokio, данные хранятся в SQLite через rusqlite. Он не использует WordPress, PHP или MySQL. Служба, ручные проверки и очистка тестовых записей реализованы на Rust; Python не требуется.

## Сборка и проверки

Из этого каталога на Linux x64 с Rust 1.99.1 и C-компилятором:

```bash
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --check
cargo build --release --locked
```

SQLite включается в исполняемый файл. Сборки нужно делать для архитектуры и системной библиотеки целевого сервера. Дистрибутив сервиса — `target/release/giveaway-scout-telemetry`; шаблон панели включён в него при компиляции.

## Контракт и хранение

- Сервис слушает только `127.0.0.1:8793`; внешние HTTPS-запросы принимает Nginx.
- `POST /giveaway-scout/api/v1/active` принимает JSON с двумя строками: `installationId` (канонический UUID v4) и `appVersion`. Максимум 512 байт, без chunked-передачи. Успех — HTTP 204.
- `GET /health` возвращает статус; `GET /metrics` — JSON; `GET /dashboard/` — HTML-панель. Они доступны локально; Nginx открывает наружу только приёмник и защищённую панель.
- Соль читается из `$CREDENTIALS_DIRECTORY/installation-salt`, предоставляемого systemd. Требуется минимум 32 байта.
- База по умолчанию: `/var/lib/giveaway-scout-telemetry/usage.sqlite3`; для локального стенда можно задать `TELEMETRY_DB`.
- Схема SQLite и HMAC-SHA256 совместимы с прежним Python-сервисом. При обновлении нельзя менять существующую соль: иначе те же установки получат другие серверные идентификаторы.
- Активность хранится 90 дней; неактивные установки удаляются. Обслуживание выполняется при запуске, раз в час, при записи и чтении метрик.
- Запросы, адреса клиентов, UUID и заголовки не журналируются. Одновременно обслуживаются до 32 соединений с ограничениями времени и размера запросов.

## Развёртывание

Первичная установка на подготовленном сервере выполняется от root:

```bash
bash deploy.sh /путь/к/giveaway-scout-telemetry
```

Скрипт отказывается перезаписывать существующее развёртывание. Он создаёт отдельные соль и реквизиты панели, настраивает службу и маршруты Nginx. Настройки ориентированы на сервер владельца `historyalive.ru`; это не универсальный установщик.

Для обновления уже работающей службы:

```bash
bash update.sh /путь/к/giveaway-scout-telemetry
```

`update.sh` сохраняет SQLite вместе с WAL, исходные метрики и unit с Rust-командой в закрытом `/root/backups/`. База копируется после остановки службы. Скрипт меняет `ExecStart` существующего unit и исполняемый файл, сохраняет соль, пароль панели, ограничения systemd и Nginx. Прежние Python-файлы удаляются из каталога службы. После запуска проверяет HTTPS-приёмник, дедупликацию, вход в панель и страницы сайта. По решению владельца возврата к Python нет: при ошибке служба останавливается, данные остаются для исправления Rust-версии.

Отдельный ручной запуск проверок на сервере от root:

```bash
/opt/giveaway-scout-telemetry/giveaway-scout-telemetry verify-live
```

Проверка отправляет два запроса с собственным синтетическим UUID и удаляет только свою запись. Обычные Rust-тесты не обращаются к production-серверу; совместимость прежней БД проверяется по синтетическому SQLite-дампу и метрикам, созданным Python-реализацией.

Для удаления фиксированной синтетической записи ручного теста клиента:

```bash
/opt/giveaway-scout-telemetry/giveaway-scout-telemetry cleanup-client-probe
```

Команда отказывается удалять запись, если её версия отличается от `1.0.0-client-test`.
